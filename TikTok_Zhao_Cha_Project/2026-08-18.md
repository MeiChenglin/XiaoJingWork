## GameLanch.ts

游戏的启动入口组件，负责在游戏最开始时初始化所有管理器（Manager），相当于游戏的总电源开关。



### import

**具名导入**：import { EventMgr } from '...'【花括号里的名字必须和导出时完全一致】

**默认导入**：import GameData from '...'【对应导出文件里的 `export default`，名字可以自定义】



### 解构装饰器工具

例：`const { ccclass, property } = _decorator;`

把 `_decorator` 对象里的两个属性取出来赋给同名常量。

上面代码等价于：

`const ccclass = _decorator.ccclass;`

`const property = _decorator.property;`



### 类声明与装饰器

`@ccclass('GameLanch')` — 装饰器，Cocos Creator 专用，告诉引擎这个类叫 GameLanch，可以挂到节点上。

`extends Component` — 继承，`GameLanch` 是 Cocos 的 `Component` 的子类，拥有 `onLoad`、`update` 等生命周期方法。

`export class` — 导出这个类，让其他文件可以 `import` 它。



### 静态单例

`public static Instance: GameLanch = null as unknown as GameLanch; `

- `static` — 静态属性，属于类本身而不是某个实例，通过 `GameLanch.Instance` 访问，而不是 `this.Instance`。【通过 类名.xxx 的形式使用。】
- `null as unknown as GameLanch` — 双重类型断言。TypeScript 不允许直接把 `null` 断言为 `GameLanch`（类型差异太大），所以先断言为 `unknown`（万能中间人），再断言为目标类型。这是一种"我知道我在做什么，编译器请闭嘴"的写法。

这是单例模式：整个游戏只存在一个 `GameLanch` 实例，通过类名全局访问。



### @property 属性

cc 的属性检查器 面板可以看见。

```ts
@property(Boolean)
public isNetMode: boolean = false;

@property(String)
private wsUrl: string = "ws://127.0.0.1:6081/ws"; 

@property(TextAsset)
private pbTexAsset: TextAsset | null = null;

@property(Prefab)
public UILoading: Prefab = null as unknown as Prefab; 
```

- `@property(类型)` — Cocos 装饰器，让这个属性出现在编辑器 属性检查器 面板，可以拖拽赋值。
- `public` / `private` — 访问修饰符。`public` 任何地方可访问，`private` 只有这个类内部可访问。
- `TextAsset | null` — 联合类型，变量可以是 `TextAsset` 类型，也可以是 `null`。



### onLoad 生命周期

```ts
onLoad(): void {
    if(GameLanch.Instance === null) {
        GameLanch.Instance = this;
    }else {
        this.destroy();
        return;
    }
}
```



- `onLoad(): void` — 返回类型标注为 `void`，表示这个方法不返回任何值。
- 单例守卫逻辑：如果已经有实例了（`Instance !== null`），就销毁自己并立即 `return`，防止重复初始化。



### 动态添加组件

```ts
this.node.addComponent(ResMgr);
this.node.addComponent(SoundMgr);
this.node.addComponent(TimerMgr);
this.node.addComponent(EventMgr);
this.node.addComponent(UIMgr);
this.node.addComponent(LanguageMgr);

if(this.isNetMode) {
    this.node.addComponent(ProtoMgr).Init(this.pbTexAsset);
    this.node.addComponent(NetMgr).Init(this.wsUrl);
}
```

- `this.node` — 当前脚本挂载的节点。
- `addComponent(XxxMgr)` — 把各个管理器脚本动态挂载到同一个节点上，让它们随节点生命周期自动初始化。
- `.Init(...)` — `addComponent` 返回新添加的组件实例，直接链式调用它的初始化方法（方法链）。
- `if(this.isNetMode)` — 网络模块是可选的，通过 属性检查器 面板的 `isNetMode` 勾选框控制是否启用。



### 其他

单例守卫：Cocos 中，如果同一个场景里不小心放了两个挂有 `GameLanch` 脚本的节点，引擎会创建两个 `GameLanch` 实例，导致所有管理器被初始化两遍，出现各种奇怪的 bug。

单例守卫就是在代码里加一道检查关卡，强制保证只有第一个实例能活下去。







## GameApp.ts

`GameApp.ts` 是游戏的逻辑入口。`GameLanch` 负责启动所有管理器，而 `GameApp` 负责真正开始加载资源、进入游戏界面。



### 资源包配置对象

```ts
var resPkg = {
    "GUI": SpriteFrame,
    "UIPrefabs": Prefab,
    "Sound": AudioClip,
    "jsonData": JsonAsset,
}
```

对象字面量：用花括号 `{}` 直接写出来的对象叫对象字面量。

这里 key 对应 Cocos 工程里的 Bundle 文件夹名，value 是告诉加载器该文件夹里的资源是什么类型。



| 关键字  | 作用域             | 可重新赋值 | 推荐程度 |
| :------ | :----------------- | :--------- | :------- |
| `var`   | 函数作用域（较老） | 可以       | 不推荐   |
| `let`   | 块作用域           | 可以       | 推荐     |
| `const` | 块作用域           | 不可以     | 推荐     |

这个对象是什么？ 它是一张"资源清单"，key 是 Bundle 文件夹名，value 是资源类型。意思是：

- `"GUI"` 文件夹下装的是 `SpriteFrame`（图片帧）
- `"UIPrefabs"` 文件夹下装的是 `Prefab`（预制体）
- `"Sound"` 文件夹下装的是 `AudioClip`（音频）
- `"jsonData"` 文件夹下装的是 `JsonAsset`（JSON 数据）

后面 `ResMgr` 会遍历这个对象，按类型批量加载资源。



### 类声明 + 单例守卫

```ts
export class GameApp extends Component {

    public static Instance: GameApp = null as unknown as GameApp

    onLoad(): void {
        if (GameApp.Instance === null) {
            GameApp.Instance = this;
        } else {
            this.destroy();
            return;
        }
```

和 `GameLanch` 完全一样的模式：静态单例 + 守卫。

注意这里没有 `@ccclass` 装饰器。 因为 `GameApp` 不需要在编辑器 Inspector 面板上配置属性，它是被 `GameLanch` 用 `this.node.addComponent(GameApp)` 动态添加的，所以不需要装饰器也能工作。



### EnterGame — 进入游戏

```ts
public EnterGame(): void {
    console.log('enterGame');

    SdkManager.Instance.trackEvent("10000", {})
    UIMgr.Instance.ShowUIPrefab(GameLanch.Instance.UILoading);
    
    ResMgr.Instance.preloadResPkg(resPkg, (now: any, total: any) => {
        console.log(now, total);
        EventMgr.Instance.Emit("loadProgress", Math.floor(now * 100 / total));
    }, (error?: Error) => {
        if (error) {
            console.error('[GameApp] 公共资源加载失败，已停止进入主界面：', error);
            return;
        }
        this.EnterLoadingScene();
    });
}
```

箭头函数的关键区别：`this` 不会变。在箭头函数里写 `this`，指的还是外面的 `GameApp` 实例。如果用普通 `function`，`this` 可能会指向别的东西。这在回调中非常重要。

`any` 意思是"什么类型都行，别给我做类型检查"。

`error?: Error` 可选参数

`?` 表示这个参数可以不传。调用时可以 `callback()` 也可以 `callback(someError)`。



### EnterLoadingScene — 进入主菜单

```ts
public EnterLoadingScene(): void {
    SdkManager.Instance.trackEvent("10001", {})
    let clip = ResMgr.Instance.getAsset("Sound", "bg");
    SoundMgr.Instance.playBgMusic(clip,true);
    
    UIMgr.Instance.ShowUIView("UIPrefabs", "Menu");
    UIMgr.Instance.RemoveUI("Loading");
}
```

1. 上报埋点 `"10001"`（标记资源加载完成）
2. 从 `"Sound"` bundle 里取出 `"bg"` 音频，播放背景音乐（`true` = 循环播放）
3. 显示主菜单界面 `"Menu"`
4. 移除之前的 `"Loading"` 界面



### 其他

```
SdkManager.Instance.trackEvent("10000", {})
```

上报数据统计事件，`"10000"` 是事件 ID，`{}` 是空的附加参数。用来追踪"有多少玩家启动了游戏"。



回调就是"把一个函数当参数传给另一个函数，让它在合适的时机替你调用"。



```
Math.floor()
```

向下取整。`Math.floor(3.7)` = `3`，`Math.floor(99.9)` = `99`。
